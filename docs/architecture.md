# Architecture

This is a static single-page app (Vite + React + TypeScript) deployed to GitHub Pages under
`/pokemon-tcg-pocket-deck-builder/`. There is no server, login or tracking; decks and imported screenshots stay in the browser.

## Layers

```text
src/lib/        framework-free TypeScript (ESLint forbids React/app imports here)
  codec/        deck-share payload encode/decode (pure functions, byte-exact fixtures)
  cards/        catalogue loading, indexes, search, ID/name resolution, image-URL adapter
  deck/         deck model, validator, undo/redo history, versioned storage, share URLs, import/export
  qr/           QR generation (qrcode-generator, v9-H) and decoding (jsQR + screenshot recovery, in a worker)
  export/       QR-card image layout (pure) and painting (Canvas2D)
src/app/        React UI: catalogue, builder, QR panel, import dialog, QR-card export
scripts/        data sync (sync-data.ts), gameplay importer, build budget check
data/           checked-in sync inputs: trimmed gameplay catalogue, overrides, known gaps
public/data/    generated catalogue snapshot + meta (the only card data the site loads)
tests/          Vitest unit/integration tests and fixtures; e2e/ holds Playwright smoke tests
```

It's a single package, not a monorepo. Lint enforces the `src/lib` boundary, so the core could move to
`packages/*` later without changes.

## Deck-code payload
The format is documented in `docs/qr-format.md`, credited to KevinGutowski/tcgp-deck-qr:
`base64( u8 nT, nT×u24be(trainer entity + 10,000,000), u8 nP, nP×u24be(pokémon entity), u8 nE, nE×u8 energy )`.
There is one ID per copy. Energy values are 1–8, with 1–3 distinct values per deck. The QR symbol is version 9,
error correction H, byte mode, the same as the game's own codes.

### Fixtures
The payload format was confirmed in the game on 2026-09-23. A code generated by the original Python
prototype for a Mega Lucario ex deck (payload in `tests/fixtures/payloads.json`) imported correctly on an
iPhone. That payload and the tcgp-deck-qr reference payload are regression fixtures: they must decode
and re-encode byte for byte.

## Data flow
`npm run sync-data` does the following:
1. Reads the flibustier npm package and `data/upstream/gameplay.json`, and checks both schemas.
2. Joins them on the set+number key (with the PROMO-A → P-A alias).
3. Parses entity IDs and normalises names.
4. Groups prints by entity.
5. Stops with an error on ambiguity or regressions.
6. Writes `public/data/cards.v1.json` + `meta.json`.

At runtime the app fetches that one file, builds its indexes and never calls a third-party API.
Images are the only third-party requests, and they are hotlinked with a text fallback.

## State
The deck draft lives in React state with an undo/redo history. It is autosaved to `localStorage`
under the key `pdl:v1`, a versioned envelope with a `migrate()` chain. A share URL puts the payload in
the hash (`#d=…&n=…`), so it never reaches a server log.

## Performance and memory
- The catalogue snapshot has a gzip budget, checked by `scripts/check-budget.mjs`.
- Art is lazy-loaded at thumbnail size, and the card grid renders more cards as you scroll.
- QR decoding runs in a Web Worker.
- Vitest and Playwright each run with a single worker to keep memory use low. Playwright runs WebKit only.
